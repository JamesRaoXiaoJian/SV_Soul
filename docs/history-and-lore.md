# 对话历史与背景资料检索（模组 1.7.0）

背景库服务于 NPC 对话，包含人物背景、亲友关系、地区组织、世界设定、节日和常见物品。个人记忆、当前存档事实、公共背景分别管理。查看旧聊天不会把整段历史重新发送给模型。

## 资料覆盖与来源

随模组提供 107 条经过整理的资料：48 个现有角色条目的背景、12 项节日介绍、47 条地区／组织／世界与服务背景。每条有稳定 ID、事实键、来源、语言、适用版本及核对日期。`???` 的真实身份没有可靠依据，资料保留未知。

运行时通过 SMAPI 的游戏内容接口读取当前有效资源，包括其他内容模组的修改及本地化文本：

- `Data/Characters`：生日和亲友关系，具体称谓由游戏本地化字符串提供。无额外解锁条件、始终显示在日历上的生日属于公共信息；其他生日及亲友详情限定本人和资料中明确的亲友。
- `Data/Objects`：常见农产品、食物、动物产物、加工品、矿物、鱼类和材料的名称与说明。过滤任务物品、隐藏物品及非物品地图节点。
- `Data/Festivals` 与 `Data/PassiveFestivals`：传统节日与沙漠节、鳟鱼大赛、鱿鱼节、夜市的日历和开始时间。被动节日的游戏条件在请求时由游戏判断；当天正在举办的被动节日也进入实时场景，支持“今天是什么节日”。

实际 Stardew Valley 1.6.15 资源的离线检查生成 402 条运行时资料，其中常见物品 329 条、节日日历 12 条，其余为生日和亲友关系；与整理资料合计 509 条。安装不同内容模组后数量会变化。

数据源清单与覆盖检查结果在 `artifacts/tests/lore-corpus-inventory.json`。整理资料的许可及出处见 `assets/lore/NOTICE.md`；原始游戏资源及完整 Wiki 页面不随发布包分发。

## 检索与知情边界

使用已有 Lucene.NET 的 CJK 分词和 BM25，不增加向量数据库、网络检索服务或模型调用。别名索引识别中英文名称及常用称呼；优先完整名称，避免把“元素战争”误匹配成另一场“战争”。英文别名检查词边界，不把 `same` 当成 `Sam`。

生日、亲友、职业与节日日程问题按类型筛选。“你妈妈是谁”指向当前角色；“我妈妈……”不会当作 NPC 的家庭。明确的第三人称和地点追问可使用最近两轮里最后出现的实体，“这里是什么地方”可以使用当前 NPC 所在地点，“今天是什么节日”可以使用当前节日；无关安慰和闲聊不继承旧话题。

Lucene 在排序前筛选角色知情、资料版本和透露条件。`KnownBy` 限定知情角色；`Condition`、`RequiredAll`、`RequiredAny` 组合约束透露条件。支持当前事件、已收邮件、关系、好感和游戏内容条件。条件未知或不满足时不返回事实。熊及 `???` 不默认具有人类的公共百科知识。

角色知道但暂不愿讲述的内容，只给模型一个不含秘密内容的保留提示。这样可以自然拒绝深入，而不用假装从未听过。玩家解锁某段剧情不会把知识自动授予其他角色。

每轮最多 3 条、1,000 字符，整条保留，不截断事实。没有相关结果时返回空，不补最近资料。相同事实键优先使用当前有效游戏资源；婚姻、住所、当日天气等当前事实优先于静态背景。资料不会自动写入个人经历记忆。

## 性能与生命周期

游戏资源在主线程复制为独立数据，Lucene 索引在后台构建。共享索引不保存某个玩家的解锁权限，权限随每次请求传入。内容失效时旧索引停止服务；后台旧代结果会丢弃，新的索引就绪后统一切换。相关资源变化、存档切换和语言变化都会触发更新。聊天不等待建库完成。

索引仅存在内存中，读档后从当前资源重建。不存在必须保留的临时缓存目录。刷新合并为单个后台任务；当前资料规模下重建整个相关资料索引，不维护复杂的增量数据库。

提示词继续以 8,000 字符为目标，个人记忆与背景分别预留额度，保留人设和表达方向。规则、当前状态及角色表达不由资料内容重写。背景源编号只用于调试，不要求 NPC 在台词里引用。

## 历史窗口

重开同一存档／玩家／NPC 的对话时加载最近 50 条消息；滚动到顶部继续分页。请求状态属于会话，关闭窗口再打开仍可看到等待和完成结果。失败是请求状态，不作为 NPC 台词保存。读取旧记录不重复加开场白、不重新提取记忆；未保存退出的回滚规则保持不变。

## 维护与验证

直接编辑 `assets/lore/*.json` 中的资料；同目录的 JSON 均为条目数组。`Source` 指向原文或原始游戏资源键，`GameVersion` 指定适用的游戏主／次版本。新增秘密或结局内容必须标注知情者和透露条件；不要直接导入含分支的事件脚本。

离线检查：

```bash
source scripts/env.sh
python3 scripts/validate-lore-corpus.py
dotnet run --project tests/Core
dotnet run --project tests/Core -- --native-lore
dotnet build -c Release -p:GamePath="$PWD/game" -p:EnableModDeploy=false
```

`--native-lore` 使用本机 `tools/*-raw.json` 中提取的已安装游戏资源。这些本地授权资料不进入源码包或发布包。普通 Core 检查不要求这些资料。真实 API 测试使用合成场景，不读取或修改玩家存档。

验证记录与逐项验收见 `docs/lore-validation.md`。按用户要求，本轮没有启动游戏或操作游戏界面；界面渲染和真实 SMAPI 事件触发不属于本轮实机验证范围。
