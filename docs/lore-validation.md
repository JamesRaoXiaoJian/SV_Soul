目标：完成已确定的原版 1.6 NPC 对话背景库与轻量检索，保留已有记忆、人设和游戏状态优先级。验证按用户要求在不开游戏、不操作界面的条件下完成。

| 要求 | 实现与证据 |

| 地区、组织、世界、服务资料 | 47 条整理背景，每条保留来源；不把默认住所或历史就业当作当前状态 |

| 轻量、有限上下文 | Lucene/CJK/BM25、别名索引；最多 3 条／1,000 字符；无额外模型调用；预算逐查询检查 |

## 检索评测

`tests/fixtures/lore-queries.json` 包含 91 条人工标注的问题，包括间接职业提问、日历、物品、中英文别名、剧情条件、角色隔离、追问和零召回情况。测试输出逐问题命中 ID，并检查条数与字符预算。结果在 `artifacts/tests/lore-quality.json`，而不是只报告合成数据性能。

万条资料的预热基准使用 200 次本地查询；具体 P95 在各平台的测试日志中。该基准衡量检索耗时，不等同于模型回答正确率。

## API 样例

`lore-live-output.json` 保存 8 个初始真实 API 回答，`lore-live-followup-output.json` 保存修改后 3 个针对性复测：

- 生日／家人、常见物品和节日时间有具体依据。
- 阿比盖尔婚后确认与玩家住在农场。
- 法师未满足透露条件时表示暂不细谈；满足条件后回答矮人与影子人的战争。
- 普通安慰没有强行塞入百科资料。

这些样例是有限的生成测试，不保证模型永远不犯错；事实筛选与资料预算另有确定性测试。

## 验证边界

本轮没有启动游戏、操作手柄或鼠标键盘，没有修改玩家存档，也没有替换正在使用的模组安装。GameContent 和 GameStateQuery 适配经过当前游戏引用的编译检查，数据转换使用真实安装资源离线验证；实际 SMAPI 事件触发与界面表现需在之后用户允许的游戏测试中观察。
